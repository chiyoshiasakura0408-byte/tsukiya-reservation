# 顧客ブラックリスト・予約拒否

顧客管理でお客様を選択し、「ブラックリスト・予約拒否」に理由を入力して登録します。解除にも理由が必要です。登録・解除履歴を保持し、予約拒否のお客様のみを一覧表示できます。初期状態では誰も登録されません。

新しい予約の作成前に、顧客ID、電話番号、メールアドレスのいずれかの一致で拒否します。電話番号は全角・ハイフン・日本の国番号表記を正規化し、メールは大文字小文字を区別しません。氏名だけでは拒否しません。共有の連絡先を持つ他の方にも一致するため、登録者は連絡先を確認してください。連絡先未登録の場合は顧客IDを指定した予約だけを拒否できます。別の連絡先・未連携のアカウントからの申込みを本人と判断することはできません。

ホームページ（日本語・英語）、電話・直接予約、LINEコンシェルジュ、業務LINEからの新規作成で、予約保存・請求・確定通知より前に判定します。拒否理由は認証済みの顧客管理画面だけに表示します。一般のお客様向けのエラーは共通文面です。

既存予約の取消・返金や既存請求の変更は行いません。外部Square予約の受信では、拒否対象の新規レコードを店内システムへ取り込みません。Square側の予約そのものは自動取消しないため、Squareの独立した予約受付を使う場合はそちらの運用も確認してください。

設定・予約登録は同じSQLiteの書込みトランザクションで直列化します。設定変更は版番号を照合し、古い画面からの上書きを拒否します。設定用POSTは認証、専用ヘッダー、公開先のOriginを確認します。登録済みの旧連絡先は、プロフィール変更後も解除まで照合対象として保持します。

検証: `python -m unittest discover -s tests -p test_booking_blocks.py -v`

13項目: 正規化、同姓同名、顧客ID、解除・履歴、入力と競合、既存予約維持、過去連絡先、保存状態、Square取込、業務LINE、コンシェルジュ、HTTP認証とCSRF、予約・請求の副作用なし。
