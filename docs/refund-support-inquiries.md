# カード返金のSquare自動問い合わせ

新しく予約を取り消し、Squareカード決済の返金対象額がある場合、取消と同じDBトランザクションで問い合わせを予約する。
既存の5分間隔ワーカーから、返金処理とは独立してSquareサポートへメールを送信する。返金の朝倉承認は変更しない。

- 宛先は `square-jp@help-messaging.squareup.com` に固定。送信には既存のSMTP設定と店舗の送信元メールを使う。
- 元のSquare決済と店舗・注文・金額を照合し、決済日時（日本時間）、取引額、返金額、カード会社、下4桁、決済ID、店舗IDを記載。お客様名・連絡先・カード番号全体・トークンは含めない。
- 残高不足の発生は推測せず、残高不足の場合の振込先・入金手順と追加のアカウント確認方法を問い合わせる。送信元をSquare登録メールと偽って記載しない。登録メールや代表者の確認を要求された場合は店舗で返信する。
- 口座への振込や返金の実行、返信の自動解釈は行わない。
- 未決済、銀行振込、返金0円、Sandbox、すでに返金済みの決済は送信しない。導入前の返金は `SKIPPED_LEGACY` として一括送信を防ぐ。
- 予約単位の主キーとDBでの送信権獲得により並列送信・再起動でも重複を防ぐ。SMTP送信結果が不明なら `UNKNOWN` とし自動再送しない。決済データ取得の失敗だけは5分・10分間隔で計3回まで試行する。
- 決済管理の返金欄に、送信待ち・送信済み・設定待ち・要確認・送信結果不明等を表示。`SENT` はSMTP受付を意味し、サポートによる受付・回答を保証しない。

Square公式手順：https://squareup.com/help/jp/ja/article/8496-troubleshoot-customer-refund
以前の振込先が分かっていても、今回のサポート案内を受けてから振り込む。

検証：`python -m unittest discover -s tests -p 'test_refund*.py' -q`
すべて一時SQLite・Square/SMTPスタブを使い、実送信・実返金は発生させない。
